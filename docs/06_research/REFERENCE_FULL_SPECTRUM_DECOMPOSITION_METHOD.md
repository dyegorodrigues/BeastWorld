# BeastWorld — Full-Spectrum Reference Decomposition Method

**Date:** 2026-09-05  
**Status:** `RESEARCH GOVERNANCE / NOT CANON`

## Purpose
The author does not want references reduced to one trick each (`Fog Hill = fights`, `JJK = relationships`, `Solo Leveling = progression`). Those shorthand labels are routing aids only.

When a reference becomes important to a real BeastWorld problem, study the **whole work/system at the depth that earns its keep**.

## Full-spectrum dimensions
For books, manga/manhwa/donghua, anime, film, television, games and other narrative worlds, inspect as relevant:

### A. Foundational architecture
- premise;
- promise to audience;
- thematic spine;
- macro mystery;
- endpoint/horizon;
- scope control;
- what the work refuses to explain early.

### B. World as lived environment
- history;
- geography;
- travel and distance;
- economy;
- food/work/daily life;
- class/status;
- religion/belief;
- institutions;
- law;
- warfare;
- knowledge transmission;
- cities/settlements;
- ecological consequences;
- how locations exist when protagonist is absent.

### C. Character engineering
- protagonist desire/contradiction;
- competence;
- wounds/needs;
- side-character independence;
- mentor construction;
- rivals;
- temporary antagonists;
- villains;
- relationships that change behavior;
- humor/chemistry;
- romance;
- ideological mirrors;
- character exits/deaths/returns;
- how growth changes relationships rather than only statistics.

### D. Plot and story architecture
- opening promise;
- inciting disruption;
- arc structure;
- escalation;
- reversals;
- reveals;
- mysteries;
- subplots;
- causal linkage;
- quiet intervals;
- climax design;
- aftermath;
- time jumps;
- book/season boundaries;
- setup/payoff distance.

### E. Power / magic / martial system
- fundamental resource;
- access;
- inheritance;
- learning;
- cost;
- limits;
- exceptions;
- counters;
- specialization;
- team synergy;
- progression;
- healing;
- forbidden techniques;
- societal consequences;
- how rules manufacture choices.

### F. Combat engineering
- martial vocabulary;
- weapon/body relationship;
- choreography;
- spatial legibility;
- pacing;
- reversals inside fights;
- terrain;
- information;
- team roles;
- special techniques;
- audiovisual momentum;
- camera/editing/animation language where applicable;
- sound/music;
- how a fight changes story/relationship/world state.

### G. Visual / production design
- silhouette;
- costume/wardrobe;
- architecture;
- environment;
- materials;
- props/weapons;
- iconography;
- color/lighting;
- cultural differentiation;
- creature design;
- effects language;
- how visual style encodes history/society rather than cosplay.

### H. Audience pleasure and emotional rhythm
- what viewers/readers wait for;
- awe;
- humor;
- tension;
- brutality;
- horror;
- wonder;
- comfort/ordinary life;
- romance;
- catharsis;
- progression pleasure;
- mystery pleasure;
- character attachment.

### I. Production / adaptation intelligence
- medium-specific strengths;
- what changes between source and adaptation;
- pacing constraints;
- action production;
- visual identity;
- franchise/game adaptability;
- what would survive translation to prose/webcomic/anime/live action/game.

### J. Failure analysis
- weak arcs;
- pacing collapse;
- cast obsolescence;
- power inflation;
- exposition overload;
- derivative aesthetics;
- plot armor;
- repetitive antagonists;
- world that exists only around protagonist;
- production limitations mistaken for story rules.

## Reference card output
A serious reference study should normally answer:

1. **What does this work do unusually well?**
2. **What mechanism produces that effect?**
3. **Where does it fail or become expensive?**
4. **Which BeastWorld problem could this lens help solve?**
5. **What package must not be imported?**
6. **What transformed BeastWorld-specific hypothesis emerges?**
7. **What scene/system test can falsify that hypothesis?**

## Compatibility rule
Admiration is not compatibility.

A popular or loved work can still be a poor reference for a specific BeastWorld problem. Conversely, a work the author does not personally enjoy may contain one useful engineering solution; that solution should be explained before being borrowed.

Never invoke an obscure reference as authority without explaining the transferable mechanism.

## Routing principle
Do not load all reference research for every conversation.

Use this method to select references by the current design problem, then do full-spectrum decomposition only where it can materially improve a decision.

**Study broadly; retrieve narrowly; transform aggressively; copy no package.**
